# This Week - Spec

A phone-first personal task app. One self-contained web page, no server, no
account, no build step. Everything lives on the device it runs on.

## What it is for

Capture everything the moment it appears (a thought, a photo of a paper list),
keep one honest board of what is Inbox / Now / Next / Later, and plan the
current week loosely - days, not clock times.

## Files

- `index.html` - the whole app (markup, styles, logic). No dependencies.
- `manifest.webmanifest` - lets phones install it to the home screen; the
  install icon is embedded in it (no separate image files).

The iPhone home-screen icon is generated by the app itself at runtime (a
canvas-drawn mark injected as the apple-touch-icon), so there are no binary
assets to host.
- `SPEC.md` - this file.

Hosting: any static file host, or just open `index.html` in a desktop browser.
On a phone it needs to be served over HTTPS for install and reliable storage.

## Concepts

- **Task**: title, stream (optional), rough size (15m / 30m / 1h / 2h / half
  day / full day), column (Inbox / Now / Next / Later), optional day in the
  current week, optional not-before date, notes, photos.
- **Stream**: a color-coded work stream or life area. Any number of them;
  tasks pick one or none.
- **One-off**: done means done.
- **Recurring chore**: has a cadence (every N days / weeks / months). Marking
  it done parks it until the next occurrence. It never ends.
- **Finite course / project**: has the owner's estimate in their own words
  (e.g. "10-12 hours") plus a single working total used only for counting
  down. Logging time or marking sessions done decrements it; at zero the
  course is finished and disappears. It never becomes a habit.
- **Not-before date**: parks a task (shown dimmed with its date) until that
  day. For things that cannot or should not start yet.
- **Week view**: Sunday to Saturday. Assigning a task to a day is a rough
  plan, not a schedule; day rows show the summed rough sizes so overloaded
  days are visible.

## Capture

- Text: the "+ Capture" button (or "+ add" on a day) opens one sheet for
  everything about a task.
- Photo: "Add photo" opens the phone camera or photo library
  (`<input type="file" accept="image/*">`). Photos are downscaled to ~1200px
  JPEG and stored locally, attached to the task. Photos of handwritten lists
  stay photos - the app does not transcribe handwriting.

## Board

Four columns (Inbox / Now / Next / Later). Every card has explicit move
controls: ◀ ▶ between columns, ▲ ▼ to reorder, "+ day" to schedule,
"unschedule" to take it off the week. Long-press drag between columns also
works where the browser supports it, but the buttons are the guaranteed path
on every device.

## Storage

- IndexedDB (database `this-week`, stores: tasks, streams, photos, meta).
  Typical phone capacity is hundreds of MB - thousands of tasks and photos.
- If storage is unavailable (private browsing, embedded preview), the app
  runs in memory and says so at the top: changes last only while the page
  is open.
- The app makes no network requests. There is no account, no sync, no
  analytics. Task data never leaves the device except when the owner
  exports it.
- Clearing browser data, or deleting the home-screen app on iOS, erases the
  list. The backup flow exists for exactly this reason.

## Backup format (export / restore)

"Download backup" saves `this-week-backup-YYYY-MM-DD.json`. "Restore" reads
a file or pasted JSON. Format:

```json
{
  "version": 1,
  "exportedAt": "2026-10-24T21:00:00.000Z",
  "tasks": [
    {
      "id": "t…", "title": "…", "streamId": "t…|null",
      "kind": "task|chore|course",
      "size": 60,                       // minutes, one of 15/30/60/120/240/480
      "col": "inbox|now|next|later",
      "order": 1761…,                   // sort key within a column/day
      "notBefore": "YYYY-MM-DD|null",
      "notes": "…",
      "day": "YYYY-MM-DD|null",         // week assignment
      "done": false,
      "photos": ["p…"],
      "course": {"totalText": "10-12 hours", "totalMin": 660, "loggedMin": 60} | null,
      "chore": {"everyN": 2, "unit": "days|weeks|months", "lastDone": null} | null,
      "created": "YYYY-MM-DD"
    }
  ],
  "streams": [{"id": "t…", "name": "…", "color": "#5b7f63"}],
  "photos": [{"id": "p…", "taskId": "t…", "dataUrl": "data:image/jpeg;base64,…"}]
}
```

Restore merges into the current data (upserts by id). Export always writes
the full current state, so any recent backup is complete on its own.

## Install on a phone

- **iPhone**: serve the folder over HTTPS, open it in Safari, Share ->
  "Add to Home Screen". It launches full-screen and keeps storage separate
  from Safari tabs.
- **Android**: browser menu -> "Add to Home screen" / "Install app".

## Deliberate non-goals

- No reminders, badges or notifications.
- No clock-time scheduling.
- No handwriting transcription (photos stay attached as evidence).
- No accounts, sync, sharing or collaboration.
- No server-side anything.

- On iOS the generated home-screen icon relies on Safari reading the
  injected apple-touch-icon at install time; if it doesn't, iOS falls back
  to a page screenshot. Cosmetic only.

## Known limits (v1)

- One device at a time. Moving between phone and desktop = export, then
  restore on the other device.
- Week view is the current week only (Sunday-Saturday).
- Drag on touch is best-effort; the explicit buttons always work.
- iOS updates can evict web-app storage after long disuse - keep a backup.
